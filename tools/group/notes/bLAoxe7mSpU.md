## 读者说了什么（转述）

1. **提问**（Joff. L.，[1]）：看不懂三种办法的区别，希望有人给代码。
2. **解答**（Dani Rey，[2]）：用 Scala 写了三个版本，都是 m1 → m2 → m3 → 打开套接字，证书只有最底层用。
   - 参数版：证书作为参数一路传下去。
   - context 版：传的是一个 context 对象，里面有证书和日志级别，最底层从中取证书。
   - 全局版：三层方法都不带参数，最底层直接读一个全局对象里的证书。
   这位读者的解释是：共享对象和 context 对象在实现上是一回事，区别在共享范围——共享对象只在这几个方法之间知道和使用，context 对象通常在整个框架的使用者之间共享。举的典型例子是 Web 框架里的请求上下文（能取到请求头、请求体、鉴权信息）。全局变量则说是早期 PHP 的常见做法。
3. **追问，无人回答**（Leung Cheng，[3]，两年后）：共享对象和 context 对象到底有什么不同？书里看着像两样东西；还是说 context 对象和全局变量是实现"共享对象"这一思路的两种方式？

## 挂到站点哪里

- 第 7 章 7.5 对应小节的正文或"常见疑问"（不是"讨论组 · 作者补充"，因为没有作者的话）：值得确认站点是否已把下面这点讲清楚——按书里原文，"共享对象"指的是顶层和底层**碰巧已经共同能访问到**的某个现成对象（书里举的是一个存放网络通信相关信息的对象），把值寄放在里面；书里随即指出这个对象自己可能也得靠透传才到得了底层。"context 对象"则是**专门为此引入**的、每个系统实例一份、装全部全局状态的对象。所以 Leung 的第二种读法不对，Dani 说的"实现上一样、范围不同"大体对但没说到"现成的 vs. 专门建的"这一层。以上是我对照本地第 2 版 7.5 节得出的，不是串里任何人说的。
- 需要指出 Dani 的 context 示例有一个书里明说要避免的毛病：context 作为参数一层层传下去，它自己成了透传变量。书里的建议是把 context 的引用存进各主要对象里，只在构造函数里显式传。站点第 7 章自测题里已经有这一点（"每个方法都传 context，它就成了新的透传变量"），所以**与已有内容重复**，不需要再加。
- 训练场：可以把"同一段调用链的四种写法"（透传 / 寄放在现成的共享对象 / 全局 / context 存为成员）做成一道辨析题，但站点第 7 章已有类似的对比素材，优先级低。
