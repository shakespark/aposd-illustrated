# Mountains to Molehills

- 原帖：https://groups.google.com/g/software-design-book/c/-3R1G0sU3zI
- 精读：2026-10-03，读到第 5 条（2023-06-01 ～ 2023-06-17）
- 主题：一位读者推销自己的 "Eventz" 方法（所有函数由事件触发、只读写一个共享的事件记录归档，自称"没有契约、函数彼此独立"）；作者用信息隐藏的观点指出它为什么站不住。
- 对应：第 5 章（信息隐藏与泄漏）；第 4 章（4.2 接口的非正式部分）；第 2 章（依赖与模糊性，2.3）；次要涉及第 18 章（事件驱动让代码不显然，18.2）
- 性质：可改编成训练题的例子 + 仅作背景（帖子本身是自我推广，和书没有直接关系）
- 优先级：B。帖子跑题，但作者的反驳是一段很干净的"隐式接口"分析，其中"没有 API 和 API 不明显是两回事"是书里没有的好说法，值得用。

## 读者说了什么（转述）

1. **推销**（Steve Jackson，[1]）：贴了一个视频，介绍把"山一样的复杂性变成土丘"的 Eventz / EventzAPI 方法，请大家指出它哪里行不通。
2. **辩护**（Steve Jackson，[3]）：称已经用它做出工资系统和 MRP 系统。以加拿大政府的 Phoenix 工资系统事故为例，认为只需按各份集体协议的条款逐日计算每位雇员的应得工资再求和，每个条款由一个独立函数计算。主张 Eventz 的函数"按定义就是模块化的"，因为被强制要求没有副作用、没有赋值语句、不允许本地持久化；数据是只追加的结构化日志，像会计里的不可变分类账，错误用新的记录冲正。
3. **第三方的建设性批评**（Gregg Irwin，[4]）：演示里重复的断言太多；应当一开始就说明适用范围是"业务事务处理"；缺少具体例子，只有断言听起来像卖万灵药。技术上这位读者觉得它像元组空间 / 黑板模型 / MUMPS 等老思路的组合。看了文档后的具体疑问：记录类型用数字编号（如 `6030.00`）而且似乎是浮点数；查询结果好像是字符串，要调用方自己逐字符解析。
4. **再辩护**（Steve Jackson，[5]）：承认它回到了 1968 年的单元记录系统的思路；字段都是字符串，由各函数自行转换类型；确实像元组空间，但"简单"。

## 作者的回应

一条（[2]）。作者说明只看了视频的前十分钟，但认为已抓到核心想法，判断是**很不可能行得通**。

- **作者对该方法的概括**：所有软件都组织成由事件触发的函数，这些函数读写一个共享的事件记录归档。
- **逐条否定视频里的四个断言**（没有契约 / 函数全都独立 / 函数不能给别的函数发消息 / 每个事件与其他事件隔离）：
  - 函数之间其实在**通过归档通信**：一个函数多半要用到前面的函数写进去的信息。
  - 契约必然存在：函数会期望在归档里找到某些种类的东西。
  - 事件并不隔离，恰恰相反：每个事件都可能受它之前所有事件的影响。
- **一个类比**：这就像一个程序里每个变量都是全局变量，没有任何模块化或隐藏信息的机制；在作者看来比现有系统严格地更差。
- **书里没有的一句概括**：

  > "There is a difference between having no APIs and making the APIs nonobvious. I believe that Eventz has done the latter."（John Ousterhout，[2]）

- **举证标准**：要让作者信服，需要拿出完全用它建成的大型系统，并表明它们比用传统方法建的同类系统更容易维护和扩展。

作者没有再回复 Steve Jackson 的辩护（[3]）。

## 挂到站点哪里

- 第 5 章"边界与反方"或正文的一个例子框："把接口藏起来不等于没有接口"。要点：共享的数据存储（数据库表、消息总线、全局事件日志）是一种隐式接口；各方对其中数据格式和含义的约定就是契约，只是没写下来，于是成了 2.3 节说的"模糊性"。用作者的全局变量类比。不必点名 Eventz，说"有读者提出过一种'所有函数只通过共享事件日志交互'的方案"即可。
- 第 4 章 4.2（接口的非正式部分）：一句话交叉引用。
- 训练场：改编成一道"找出隐藏的依赖"题——两个 C++ 函数表面上互不调用，只通过一个共享的 `std::map<std::string, std::string>` 记录库交换数据；问：它们之间有没有接口？接口是什么？改其中一个的字段名会发生什么？Gregg Irwin 指出的"查询返回字符串、调用方自己解析"可以作为题目里信息泄漏的第二个点。代码原创。
- 项目（minikv）：如果有模块间靠共享键约定通信的地方，可以引用这条教训。
