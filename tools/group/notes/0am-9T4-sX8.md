# Informal interface elements

- 原帖：https://groups.google.com/g/software-design-book/c/0am-9T4-sX8
- 精读：2026-10-03，读到第 7 条（2019-02-27 ～ 2019-02-28）
- 主题：4.2 节把"使用上的约束"（比如某个方法必须先于另一个调用）算作接口的非形式部分；一位读者认为这些应当叫"契约"，属于实现而不是接口。作者坚持用"接口"统称、用"形式/非形式"区分。
- 对应：第 4 章 4.2；次要：第 13 章（接口注释写什么）
- 性质：勘误或澄清（术语）
- 优先级：B。纯术语之争，作者只有一段话，但给出了一个书里没有的说法（形式部分本身也是契约），而且站点第 4 章还没有解释过"接口"与"契约"这两个词的关系，值得用一小段澄清；不值得单独成一大块。

## 读者说了什么（转述）

1. **提出问题**（Mihai Galos，[1]）：读的是第一版。引了 4.2 节讲非形式部分的那段，认为措辞可以改：使用约束不是接口的一部分，而是实现里的"契约"。举 C++20 和 Rust 计划中的契约机制为例——用专门语法给函数实现加上动态断言，调试版编译进去，发布版不生成代码。
2. **进一步说明**（Mihai，[3]）：把"形式部分"理解为编译器能静态检查的东西，代码能编译就自动满足；真正的契约在语义层面，比如"传入的整数不能为 0""调用前必须先构造对象或设置某个标志"，这些是动态的，无法静态封装。
3. **替 Mihai 澄清**（Chris Jerdonek，[4]）：Mihai 并不是说形式部分不算契约，而是反过来——"契约"是更大的词：接口指形式部分，契约 = 接口 + 非形式部分。
4. **接口和契约差不多是一回事**（Brent Welch，[5]）：如果某种语言能形式化地描述并检查比参数类型更多的东西，那只是它描述接口的语言更丰富了，描述的仍然是接口；换成"契约"这个词未必更有助于解释。像"open 之后要 close"这种约束逻辑上仍属于接口，只是更难用语言表达，得靠运行时检查。
5. **简单的词更好用**（Rafael Anschau，[6]）：用"接口 / 形式 / 非形式"思考，比用"语法 / 契约 / 各种语义 / 类型系统"这一整套概念思考负担更小；哪些算"非形式"应当由开发者根据手头的系统自己判断。
6. **Mihai 的坚持**（[7]）：运行时才检查的东西就是实现，不是接口；那些契约"装饰"的是实现。接口在这位读者看来是对被封装行为的抽象和简化，误用时抛异常是实现该做的事。最后问大家怎么看，无人再回。

## 作者的回应

作者只有 1 条：[2]，整段回复（在 Mihai 的第一条之后）。

- **坚持**：形式部分同样构成契约——调用者必须给一个字符串参数和一个整数参数、必须用某个名字调用，被调用者则给回一个整数结果。既然形式和非形式两部分都是契约，就没有理由把"契约"这个词只留给非形式部分；所以倾向于继续用"接口"统称全部，用"形式""非形式"区分两部分。
- **留了余地**："I'll reconsider your suggestion the next time I revise the book."（John Ousterhout，[2]）

本地原书文本是第二版（2021），4.2 节的说法没有变：使用约束仍被称为"类的接口的一部分"，术语仍是"形式 / 非形式"。也就是说作者重新考虑后（或没有重新考虑）保留了原措辞。

作者没有回应的：Mihai 在 [3][7] 提出的"运行时检查的东西属于实现"；Chris Jerdonek 对 Mihai 原意的澄清。

## 挂到站点哪里

- 第 4 章 4.2 对应的小节："边界与反方"里加一小段术语说明（不必用"讨论组 · 作者补充"的大块，几句话即可）——
  - 别处常说的"契约"（前置条件、后置条件、调用顺序）在这本书里全部算作接口的非形式部分；作者的理由是连签名本身也是一种契约，所以不另立一个词。
  - 判断标准是书里那句：使用模块的人必须知道的信息，就是接口的一部分，不管语言能不能检查、是编译期还是运行期检查。
  - 可以借 Brent Welch 的说法补一句：语言能检查的范围变大（类型更强、有契约语法），只是把一部分"非形式"变成了"形式"，接口本身没有变小。这一点和站点已用过的"类型能替代一部分注释"（第 13 章、专题 clean-code）相呼应。
- 训练场（可有可无）：一道判断题——"`open()` 之后必须 `close()`""参数不能为 0""函数内部用哈希表实现"三条里哪些属于接口；或者一道 C++ 题，把注释里的前置条件改成类型或断言之后，问接口是变小了还是只是换了表达方式。

## 待核实

- Mihai 说 C++20 会有契约机制：这是 2019 年 2 月的说法。印象中契约后来没有进入 C++20 标准；用到站点时不要照搬这句，需要按现行标准另行核对。Rust 的情况同样未核对。
- Mihai 引的第一版原文写的是 "one method needs to be called before another"，本地第二版是 "must be called"，只是个别用词不同；第一版其余措辞无法对照。
