## 读者说了什么（转述）

Marko Ristin-Kaufmann，[1]（在阿斯塔纳的纳扎尔巴耶夫大学给计算机本科最后一年开软件设计课，大量使用这本书）：

- 内容用讲课的方式很好讲，但很难教得有效。
- 学生课业重，很难让他们做较大的编码项目；所以改用聚焦的小练习——画类图、写伪代码，然后集体讨论，想让学生像练"套路"一样单独练某一个概念。
- 感觉学生学到的没有预期多；有些主题很难设计出有意义的练习，点名的是"信息隐藏（与泄漏）"和"通用模块更深"两章。
- 凡是 ChatGPT 能轻松做出来的作业都失去了意义，学生会直接依赖它。
- 问作者和其他读者有没有课程组织上的建议，或在类似条件下行得通的练习。

没有其他读者回复。

## 作者的回应

作者只有 1 条：[2]，整段回复。

- **基本判断**：除非学生真的在构建系统、亲身体验自己设计选择的后果，否则这本书的内容很难教。
- **自己课上的转折点**：学生开始"懂了"，是在交了第一个项目（而且项目不是玩具规模）并拿到作者的代码评审之后。评审的做法是三步：指出代码哪里太复杂；说明这份复杂性是因为违反了书里的哪条原则；演示按原则改写后代码怎样变简单。
- **两个必要条件**：要有学生自己写出来的代码的全部细节，还要有重写的机会；缺了这些就很难体会原则的分量。
- **为什么伪代码不行**：伪代码看上去可能不太复杂，"but when you have to write code that actually compiles and runs, all of the subtle dependencies and complexities appear"（John Ousterhout，[2]）。
- **承认没有答案**：如果有办法不花大力气写代码就能教软件设计当然好，但自己还没找到；谁找到了，很想听听。

作者没有回应的：ChatGPT 让作业失效的问题；哪两章难出练习题的问题。

**与书的关系**：前言讲了这门课的形式（学生做项目、大量代码评审、然后重写）；1.1 节建议读者结合代码评审来用这本书。这条回复比书里多说了一点——明确否定了"伪代码 + 讨论"这条捷径，并给出理由。

## 挂到站点哪里

- **第 1 章（目前没有讨论组材料）**："怎样用这本书／本站"附近加一块"讨论组 · 作者补充"——作者认为这本书的内容只有在"自己写出能跑的代码 → 被人指出哪里复杂、违反了哪条原则 → 重写"的循环里才学得会；伪代码和类图不够，因为细小的依赖要到代码真能编译运行时才冒出来。
- **训练场首页／项目页的说明**：这是对本站自身的一个诚实提醒。训练场的选择题、对比题属于那位教师说的"小练习"，按作者的看法它们本身不足以让人学会；所以站点应当明说训练场是用来认红旗、建立词汇的，真正的练习是 project/ 里那个能跑、有测试的重构项目，并建议读者做完任务后回头重写一遍、最好找人评审。
- 第 22 章（目前没有讨论组材料）可以用一句话呼应：读完之后该做的是拿自己的代码去试。不必单独成块。
- 专题 ai-era：读者提到"ChatGPT 能做的作业失去意义"，作者没有接这个话头，只能作为读者的观察一笔带过；该专题已有较多材料，可不加。
