# Has AI Actually Improved Software Quality in Production Systems?

- 原帖：https://groups.google.com/g/software-design-book/c/EUy3koBr1ow
- 精读：2026-10-03，读到第 18 条（2026-02-20 ～ 2026-05-12）
- 主题：AI 编程助手让写代码变快了，但在生产系统里有没有让软件质量（缺陷、性能、可维护性）真的变好；读者各自给出经验和二手数据。
- 对应：专题 ai-era；次要涉及第 3 章（战术龙卷风，3.1）、第 2 章（复杂性是一点点累积的，2.4）
- 性质：仅作背景 + 可改编成训练题的例子（Jim Lyon 的"修一个 bug 引出两个"）。**作者只发了一条，是质疑一份 PDF 的出处，没有谈 AI 与设计的关系。**
- 优先级：B。作者没有观点可引，但读者的一手经验（[6][16][17][18]）正好给 ai-era 专题提供具体场景；所有统计数字都不可直接用。

## 读者说了什么（转述）

1. **提问**（Yaowen Zhang，[1]）：软件工程的瓶颈从来不是打字速度，而是系统设计、控制复杂性、选对抽象；所以该问的不是"AI 会不会取代工程师"，而是生产环境里质量、性能、内存、体验有没有可测量的改善。
2. **"不可能"派**（J.R. Hill，[2]）：高质量代码在统计上并不常见，而 LLM 产出的是统计上常见的代码；实际水平相当于初级工程师，需要大量指导。使用者的处境会变得像软件经理：能指挥产出，但对软件本身和其中抽象的价值失去直觉。结论引 Brooks《没有银弹》：质量的瓶颈不是迭代速度。[3] Yaowen Zhang 附议。
3. **DORA 报告**（Joshua Miller，[4][7]）：2025 年的调查里多数受访者自认为 AI 改善了代码质量；[7] 补充说报告的模型同时显示对"交付稳定性"有明显负面影响，并说明受访者多来自大公司、维护多年的服务。Peter Ludemann（[5]）质疑：这是自我报告，这位读者见过的软件里连四分之一都算不上"高质量"。
4. **AI 能用来降熵的几种方式**（Jonathan Camenisch，[6]）：帮熟练工程师找现有代码的缺陷；快速做出以前不值得做的测试夹具和排错工具；让前期成本过高的"正确架构"变得做得起；让以前没时间做的**多方案比较**变得可行。最后一点直接对应"设计两次"。
5. **Gemini 生成的"研究摘要"**（Yaowen Zhang，[9][12]）：列了一串数字（重构活动下降、重复代码上升、AI 的 PR 问题更多等）。David Hess（[10]）和 Justin Hill（[11]，从 [2] 的署名看与 J.R. Hill 应是同一人）立刻要求给出非 LLM 的出处；[12] 贴了 PDF，[13] 说末尾有 34 条参考文献。Ángel Herranz（[17]）判断这份 PDF 大部分是 AI 生成的，要当学术材料用还得署名、逐条核对引用、同行评审。
6. **认知债**（Orlando Mendez，[14]）：除了技术债，还有开发者自己对系统理解的流失。
7. **"战术龙卷风"的现场例子**（Jim Lyon，[16]）：让 Copilot 修同一模块的两个 bug。一个修得简单正确；另一个，它把"用错了框架"的代码换成"自己接管并部分重做框架职责"的代码，修掉原 bug 又引入至少两个新 bug，指出后它再加代码修、再引入新的，连续 5 轮，产出一大堆本来就不该写的代码。这位读者的原话：

   > "AI agents often become tactical tornados"（Jim Lyon，[16]）

   附带一条格言：不写不需要写的代码，就不会造出不需要造的 bug。
8. **"先快后陷"**（Ángel Herranz，[17]）：起步的速度是真的，但等到要撤销错误决定、恢复系统一致性、防止偏离架构时，花的时间比预想多——是在借债。更深的担心：上下文里有一个错误前提时，模型不会质疑，而是很有把握地在上面继续盖，而且盖得很快，把负责的开发者淹没。
9. **按任务类型分三种体验**（Mahmoud Fayed，[18]）：用 Claude Code 全程提示驱动写了一个 Ring 语言的 TUI 框架（约 7 千行、107 条提示、10 小时）。这位读者的归纳：(a) 给别的语言已有的库做移植——很满意，但仍要逐行读过才敢发布；(b) 自己不懂的领域——出活快，但无力判断结果；(c) 在已有的大项目（Ring 的编译器/VM）里——查 bug 的报告约八成是错的，因为模型不懂既有架构；加功能要迭代二十多轮才把几百行压成几十行，不如自己写。

## 作者的回应

只有一条（[15]），没有涉及 AI 与软件设计的实质问题：作者指出那份《AI's Impact on Software Quality》文档没有署名，这让作者不放心，并问这份文档本身是不是 AI 生成的。可以读作一种态度——没有作者、无法追责的材料不作为证据——但作者没有再多说。
