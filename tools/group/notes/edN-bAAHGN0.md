## 读者说了什么（转述）

1. **提问**（Ron Tarrant，[1]）：刚读完透传变量那一节，没看到把单例作为一种解法。是没考虑，还是考虑过觉得不合适？
2. **补充**（Peter Ludemann，[3]）：要跑多个线程或进程时，单例也会成问题。举 Python 的全局解释器锁为例：它让某些东西更好写，却成了严重的性能问题，而且很难去掉。

## 作者的回应

作者只有 1 条：[2]，两段。

**承认遗漏**

- "A singleton class would be roughly equivalent to a global variable."（John Ousterhout）不确定当初为什么没提这层等价关系，已经记下，下一次修订书时会考虑加上。

**书里没有的表态**

- 没提的原因也许是：总的来说不太喜欢单例类。坚持一个类只能有一个实例，像是一条不必要的限制，而作者尽量避免限制。
- 具体的坏处：单例往往让单元测试更复杂——单元测试通常要频繁地创建和销毁东西，而单例一般不喜欢被销毁。

这与书里 7.5 对全局变量的批评是同一个理由（同一进程里没法并存两个独立的系统实例，而测试时常需要），作者在这里把它明确延伸到了单例。
