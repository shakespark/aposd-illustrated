# AI is good at helping you "Design It Twice"

- 原帖：https://groups.google.com/g/software-design-book/c/RROhiBErr-8
- 精读：2026-10-03，读到第 4 条（2025-06-03 ～ 2026-06-22）
- 主题：一位读者的经验——"设计两次"的真正成本在于要把方案做到一定细节才看得出哪里别扭，而 LLM 工具让快速做原型变便宜了，所以适合用来探索多个设计，而不是替人做设计。
- 对应：专题 ai-era；次要：第 11 章（设计两次）
- 性质：仅作背景（**作者没有发言**）

## 读者说了什么（转述）

1. **开帖**（Tim Etler，[1]）：
   - 对第 11 章的一点保留：书里说多考虑几个设计花不了多少额外时间；这位读者的体会是，往往要把一个方案评估到比较细、发现它哪里别扭或行不通之后，才想得到更好的设计，因为在那之前对"设计到底要完成什么"的细节还不了解。所以设计两次实际上挺费时间。
   - LLM 工具的长处正在原型：试得够快，能早早暴露方案在实践上的毛病。按这位读者的经验，这些工具在项目结构、方案选择、遵循最佳实践上做得很差，但能让人很快把东西试出来。
   - 用法：先在较高的抽象层次上探索，做低保真原型，再做高保真的；用它帮忙调研方案空间、想到自己会漏掉的方向。**先写接口，再让它填实现**，就能对设计做一次实际检验。
   - 一个反直觉的观察：生成的实现远够不上生产质量，这位读者反而认为是好事——这样就不会把原型放进生产，也不会在本该扔掉的东西上花太多心思。
   - 更一般的看法：AI 把每个领域都抬高了一层抽象，设计原则因此更重要；使用者对题目懂得越多，从模型里问出来的东西越好。"I try to use it as a tool to improve my thinking instead of trying to have it think for me."（Tim Etler）
   - 帖里说另有一篇更详细的文章，本地文件里没有链接。
2. **附和**（Mark Woodworth，[2]）：称这是见过的对"如何正确使用 LLM"最好的描述之一；对已有领域知识的人是不可少的思考伙伴，当成无所不知的代理来用则没什么用却从不缺自信。
