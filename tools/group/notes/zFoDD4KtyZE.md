- 主题：读者认为依赖注入（DI）容器能代替 7.5 的 context 对象来消除透传变量，还附带生命周期通知、通用装饰器等功能，问作者怎么看。

## 读者说了什么（转述）

1. **开帖**（Dimitar Dimitrov，[1]）：第 7 章讲了接口重复和透传变量造成的耦合。这位读者的工作经验是，依赖注入模式（把系统里各个单例的创建和接线集中到一个专门的、可复用的类里）在这方面改善了设计：不必自己建 context 对象，只要声明一个构造函数参数，由 DI 容器提供依赖。成熟的 DI 容器通常还带初始化/关闭通知、按类型列出所有受管对象、以及一批通用装饰器（事务边界、结果缓存等）。承认这些会带来模糊性的问题，但也能大幅减少代码。附言：DI 容器不必接管整个应用，给了一个约 50 行 Java 的最小实现链接。
2. **补充示例**（Dimitar，[3]）：因为作者说看不懂链接里的语言，改贴一段纯 Java 的用法：建一个注入器；把某个接口绑定到一个现成实例；把另一个接口绑定到一个实现类（按需创建并复用）；让注入器实例化应用主类，构造函数参数由它提供；利用注入器"知道所有已创建对象"这一点，遍历实现了某监听接口的对象去注册、按创建的逆序关闭所有可关闭对象。说明其中一个方法在链接的版本里还没实现。作者没有再回。
