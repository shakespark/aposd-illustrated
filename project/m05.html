背景与对应章节

server.cpp 里哪些代码应该合成一处？哪些本该分开的东西被搅在了一起？哪两个方法必须对照着读才看得懂？

Server 是 minikv 的命令层：把一行文本切成词，找到对应的处理函数，处理函数检查参数、调用 Database、格式化回复。每加一个命令，同事就复制一个现成的处理函数改一改；某天需要支持"值里带空格"，又在切词函数里加了个特殊分支。代码一直能跑，测试也全绿。

这个任务练的是第 9 章的判断：两段代码共享信息、合起来能让接口更简单、或者合起来能消除重复时，应该合；通用机制和专用逻辑应该分开；而拆分本身也有代价。做之前请读 第 9 章 · 合在一起还是分开？，重点是原书 9.3（消除重复）、9.4～9.5（通用与专用分开）、9.7～9.8（方法的拆与合，以及和 Clean Code 的分歧）。

任务与约束

  1. 消除重复：参数个数检查、键长检查、整数解析，各只保留一份。
  2. 让切词函数回到通用：它不应该知道任何命令名。"哪个命令的最后一个参数可以带空格"这件事，放到描述命令的地方去。
  3. 拆开连体方法：处理函数需要的输入通过参数传进来，不再通过成员变量和切词函数暗中交接。
  4. 如果修重复时顺手修掉了副本之间的不一致，导致某些输入的回复变了，把变化列出来，说明为什么新行为是对的。

约束：

  • make test 全绿，不许修改 tests/。已有的错误回复文字保持不变。
  • 不要为了消灭重复把代码拆成一堆两三行的小函数。拆出来的每个函数都应该能单独读懂、签名简单。
  • 只做本任务的事：每个处理函数里的 try/catch 看起来也是重复，但怎么处理异常是 m06 的题目，这次先留着。

自查清单

  • grep -c "wrong number" src/server.cpp 的结果是 1。
  • 切词函数里搜不到任何命令名。
  • Server 不再有"由一个方法写、由另一个方法读"的临时成员变量。
  • 随便挑一个处理函数，不看其他代码就能说清楚它的参数是什么、已经被检查过什么。
  • 加一个新命令（比如值里能带空格的 SETNX key value）只需要改一处登记加一个处理函数。在纸上走一遍试试。
  • make test 全绿，编译零警告。

提示

提示 1：重复的部分其实是"数据"

把每个处理函数开头的检查排成表格：命令名、最少几个参数、最多几个参数、第一个参数是不是键。你会发现各个函数之间不同的只是这几个数，相同的是检查逻辑。数据放进一张表，逻辑写一遍。

提示 2：怎么让切词函数不认识 SET

很多语言的 split 都有一个"最多切几段"的参数：切到最后一段时，剩下的部分原样保留。这个参数是通用的，和命令无关。"SET 最多两个参数、最后一个吃掉整行剩余"可以写进 SET 的命令描述里，由分派代码把它翻译成这个参数。

提示 3：整数解析值得一个函数吗

第 9.3 节说，抽出重复代码只在两种情况下划算：被抽出的代码不算太短，且抽出后的签名简单。整数解析符合吗？想想 strtoll 的几个坑：前导空白、在第一个非数字字符处悄悄停下、溢出要看 errno。基线的副本各自踩了不同的坑。反过来，处理函数里那两三行 try/catch，抽成函数后签名会是什么样？

代价与取舍

命令表每行 5 个字段，Command 的注释要解释每一个，这也是要学的接口。它划算，是因为它替换了 10 份副本，而且每个字段都是命令本来就有的属性。反例就在眼前：每个处理函数里的两三行 try/catch 如果硬抽成一个带一堆参数的辅助函数，签名会比被替换的代码还难懂。那部分留给 m06，用另一种思路（在一处聚合处理异常）解决。

继续拆下去很诱人：checkArity()、validateKey()、formatInteger()……每个两三行。那样得到的是一串浅函数，读一个命令要在五六处之间跳，又回到了"连体"。参考答案只在一个地方切开：handle() 负责"这一行是不是合法的命令调用"，处理函数负责"这个命令做什么"。判断拆得对不对，看的是两边能否各自读懂，不是行数。

splitWords 比原来"只切词"多了一个 maxWords。这是把专用知识移出去的代价。可以接受，因为这个参数本身是通用的：任何调用者都按同一个规则理解它，它不暗示任何具体命令。

审稿人仍会指出的问题

  • 每个处理函数里几乎相同的 try/catch，以及 DEL、GETRANGE 那些本可以不存在的错误：m06。
  • Store 的 set/incr/append 各自重复写日志和更新索引：m02。那是另一种重复，解法是更通用的接口，而不是抽辅助函数。
  • handleGet() 先 exists() 再 get()，bulk(s, true, true) 的两个 bool 看不出意思：m08。
